1. Introduction

The Bold Penguin Button Validator is a Node.js automation tool that validates the presence and behaviour of the <a class="button nw-button--mint-dark bold-penguin-quote">Start your quote</a> button on a list of URLs. It also tests other related CTAs (SmallCTA, StickyCTA) and verifies that clicking them leads to a valid page and that the browser’s back navigation works correctly.

The tool is designed for QA engineers, developers, and business stakeholders who need to ensure quote‑initiation flows are functional across many pages. It produces detailed HTML, CSV, and Excel reports with screenshots for easy review.

2. Features

🔍 Core Validation

  • Locates the Bold‑Penguin “Start your quote” button using multiple selectors (class, text, href).
  • Detects the actual CTA name displayed on the page dynamically, instead of relying on a fixed label.
  • Inspects the DOM for the presence of a bold-penguin-quote element and records Yes or No.
  • Simulates a click and detects:
    • Same‑tab navigation
    • New‑tab opening
    • No navigation (with fallback checks)
  • Verifies the destination page is not an error page (404, 500, etc.).
  • Uses the browser back button to return to the original page and verifies success.

🧹 Environment Handling

  • Closes cookie banners (TrustArc) and generic overlays automatically.
  • Waits for spinners / loaders to disappear (configurable timeout).
  • Retries navigation (up to 2 attempts) on failure.
  • Clears cookies between test runs to avoid state contamination.

📊 Reporting

  • Generates HTML, CSV, and Excel reports.
  • Captures full‑page screenshots for each URL (stored in screenshots/).
  • Shows per‑URL status for: overall, Bold‑Penguin button, SmallCTA, StickyCTA, and back‑navigation.
  • Includes the API URL (the href of the button) in the report.

Test Coverage

The validator is designed to cover the most common user journeys and failure points associated with the Bold Penguin quote flow. It validates each page against the expected behavior for the main CTA as well as related CTAs that may also initiate the quote process.

Coverage area What the test checks Expected result
Main Bold Penguin CTA Button presence, visibility, clickability, and navigation behavior for the primary “Start your quote” CTA. Button is found, clicked successfully, and lands on a valid destination page.
CTA selection logic Finds CTA elements by class names, text, fallback selectors, and alternative quote-related patterns. Tool correctly identifies the active quote button even if markup varies.
Same-tab navigation Validates when the user is redirected within the same browser tab. Page loads successfully and the original URL is restored after back navigation.
New-tab navigation Handles CTA actions that open a new tab or window. New tab opens without an error page, then closes cleanly and leaves the page in a stable state.
No-navigation cases Detects links or buttons that do not navigate when clicked and flags unexpected behavior. Either a valid fallback action occurs, or the action is marked as a failure.
Error-page detection Checks URL, page title, and body text for 404s, 500s, “Page Not Found,” and other error states. Pages with known error markers are marked as FAIL and reported clearly.
Back-navigation validation Confirms that the browser back button returns the user to the originating page correctly. Original URL is restored without a broken state or unexpected redirect.
Small CTA validation Tests small CTA components such as inline CTA wrappers and related quote actions. Each CTA is clicked and validated individually for navigation success and proper return flow.
Sticky CTA validation Finds sticky CTA banners and blue banner-style callouts that may lead into the quote flow. Sticky CTAs are validated for behavior, destination integrity, and return navigation.
Destination URL verification Loads the final destination URLs for the CTA flow to confirm they resolve correctly. Final URLs load normally and do not return server or content errors.
Overlay handling Closes cookie consent banners, modals, and generic overlays that can block user interaction. Page can be accessed and the CTA can be interacted with without overlay interference.
Spinner / load-state validation Waits for spinners and loading indicators to disappear before proceeding with CTA validation. Tool does not test the CTA prematurely while the page is still settling.
Desktop and mobile behavior Runs on desktop by default and can emulate mobile viewport when needed. CTA behavior is checked under the selected browser conditions with consistent reporting.
Reporting and evidence capture Captures screenshots and stores results in HTML, CSV, and Excel report files. QA and stakeholders have traceable proof of pass/fail status and destination behavior.
✅ Coverage summary: The tool validates the main quote entry point, supporting CTA components, page load quality, browser back-navigation flow, and final destination integrity — the key elements needed to confidently assess quote funnel health for a page.

3. Prerequisites

  • Node.js v16 or higher (includes npm).
  • Playwright – the tool uses Playwright to control Chromium. The required browsers are downloaded automatically on first run.
  • A CSV file containing a column named URL with the list of pages to test.
  • Internet access (to load the target pages and download Playwright browsers).

4. Setup & Installation

  1. Clone or download the script (e.g., bold-penguin-button-validator1.js).
  2. Open a terminal in the project folder.
  3. Install dependencies: 
    npm install playwright csv-parse xlsx
  4. Install Playwright browsers (if not already done): 
    npx playwright install chromium
  5. Prepare your CSV file with a header URL and one URL per row.
✅ Example CSV (urls.csv): 
URL
https://www.nationwide.com/business/solutions-center/management/commercial-vehicle-quote
https://www.nationwide.com/personal/investing/annuities/fixed-indexed/

5. Usage (Command Line)

Run the script with Node, optionally passing arguments:

node bold-penguin-button-validator1.js [options] [csv-file]

Available options

OptionDescription
--file <filename> or --csv <filename>Specify a custom CSV file (default: urls.csv).
--mobile or -mEmulate an iPhone 12 viewport (mobile testing).
--headed or -hRun with a visible browser window (headless by default).
--report or --resultsEnable report generation (default).
(no flag)If you pass a bare filename, it is treated as the CSV input.

Examples

# Use default urls.csv, headless, desktop mode
node bold-penguin-button-validator1.js

# Use a custom CSV, mobile emulation, headed mode
node bold-penguin-button-validator1.js --mobile --headed --file my-urls.csv

# Run in headless, desktop, with report generation (default)
node bold-penguin-button-validator1.js --report
⚠️ Headed mode may be blocked by Windows Application Control policy. If you see an error about “Chrome DLL” or “Application Control policy”, the tool will automatically fall back to headless mode.

6. Validation Process

For each URL in the CSV, the tool performs the following steps:

  1. Navigate to the URL with retries (max 2).
  2. Wait for page to settle – waits for DOM, load, network idle, and spinners to disappear.
  3. Check DOM presence – scans the page for a bold-penguin-quote element and records Yes or No.
  4. Handle overlays – closes TrustArc cookie banners and generic popups.
  5. Check for error page – scans URL, title, and body for 404, 500, “Page Not Found”, etc. If found, marks the page as FAIL and skips further testing.
  6. Validate Bold‑Penguin button:
    • Locate the button using multiple selectors.
    • Click it and detect navigation (same tab, new tab, or none).
    • If navigation occurs, verify the destination page is valid (no error).
    • Attempt back navigation to return to the original URL and verify success.
  7. Validate SmallCTA and StickyCTA – finds all CTAs inside <ngx-web-small-cta> and sticky blue banners, clicks each, and again checks back‑navigation.
  8. Validate destination URLs – each final URL from the button/CTAs is visited separately to confirm it loads correctly.
  9. Take screenshot – full‑page screenshot saved to screenshots/.
  10. Clear cookies – reset state for the next URL.
💡 Note: The tool uses a requireQuote flag for the main button – it expects navigation to a quote page. If no navigation occurs and requireQuote is true, the test fails.

7. Validation Rules

The tool applies the following rules to determine PASS, FAIL, or N/A:

Overall Status

  • PASS – All applicable tests (main button, CTAs, back‑nav, destination URLs) succeeded.
  • FAIL – At least one test failed (e.g., button missing, click leads to error page, back‑navigation fails).
  • N/A – No applicable tests (e.g., button not found, all CTAs skipped as tel/mailto).

Bold‑Penguin Button Status

  • PASS – Button found, clicked, destination page is valid, and back‑navigation succeeded.
  • FAIL – Any failure: button not found, click error, destination error, or back‑navigation failure.
  • N/A – Button not present (or skipped because it’s a tel:/mailto: link).

Back Navigation Status

  • SUCCESS – Click led to navigation and then page.goBack() correctly returned to the original URL.
  • FAIL – Back button did not restore the original URL, or an error occurred.
  • N/A – Not applicable (e.g., button skipped, no navigation).

SmallCTA / StickyCTA Status

  • PASS – All CTAs in that category were successfully clicked and back‑navigation passed.
  • FAIL – At least one CTA in that category failed.
  • N/A – No CTAs found in that category (or all skipped as tel/mailto).
⚠️ Important – The tool does not artificially pass failed tests. If a genuine validation fails, the result will be FAIL with a clear error description.

10. Troubleshooting

Script fails to launch Chromium in headed mode

On some Windows environments, Chromium is blocked by Application Control policy. The tool will automatically fall back to headless mode. To avoid this, run with --headed only if you are sure the policy allows it.

CSV file not found

Make sure the CSV file exists and the path is correct. The default is urls.csv in the same folder.

Button not found (N/A)

This can happen if the page uses a different selector or the button is hidden behind a login. Check the page manually to confirm.

Back navigation fails (FAIL)

This often occurs with:

  • External links – clicking a link to a different domain (e.g., semsee.com). The back button may not return to the original page.
  • Single‑page apps that use history.replaceState – the back button may not work as expected.
  • Redirects – if the destination page redirects, the back history may be altered.

The tool logs the exact reason (e.g., “Back navigation resulted in URL X instead of Y”).

Spinner detection timeout

If a page has a permanent spinner, the test will time out and mark the page as FAIL. You can adjust the timeout in the configuration (NAV_TIMEOUT, PRESENCE_TIMEOUT) if needed.

11. FAQ

Q: What does the bold-penguin column mean?

A: It indicates whether the page DOM contains an element matching bold-penguin-quote. The value is Yes or No, and it is reported separately from the functional validation results.

Q: What does “bold-penguin API URL” mean?

A: It is the resolved href attribute of the “Start your quote” button. This is often the endpoint that initiates the quote process (e.g., a Semsee or Bold Penguin API URL).

Q: Why does the tool test SmallCTA and StickyCTA?

A: These are common components on Nationwide pages that also contain quote‑initiation links. The tool ensures all ways a user can start a quote are working.

Q: Can I run the tool on a staging environment?

A: Yes – simply provide the staging URLs in the CSV. The tool does not care about the domain.

Q: What if the button is a <button> not an <a>?

A: The tool looks for both <a> and <button> with the relevant classes/text. If it’s a <button> without href, the “API URL” column will be empty, but the click and navigation will still be tested.

Q: How do I increase timeouts for slow pages?

A: Edit the constants at the top of the script: NAV_TIMEOUT, BUTTON_TIMEOUT, PRESENCE_TIMEOUT. Increase their values (in milliseconds).

Q: Can I test multiple URLs in parallel?

A: The current version runs sequentially. For parallel execution, you would need to modify the script to use workers (not included in this help).

Q: Where can I find the full validation logic?

A: Review the source code – it is well‑commented. Key functions are validateMainButton, validateButtonClick, and validateSmallCta.
